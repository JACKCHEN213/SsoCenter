# 提案：按控制器拆分路由文件

## 变更 ID

`split-routes-by-controller`

## 背景与动机

当前项目所有路由定义集中在 `route/app.php` 一个文件中。随着业务增长，该文件会持续膨胀，带来以下问题：

1. **可维护性差**：所有路由混在一起，定位特定控制器的路由需要全文搜索
2. **协作冲突**：多人同时开发不同模块时，容易在同一个路由文件中产生合并冲突
3. **可读性低**：路由文件过长，无法快速了解某个模块对外暴露的端点
4. **不符合模块化原则**：ThinkPHP 8.1 原生支持多路由文件，按模块拆分是推荐实践

## 变更目标

- 将 `route/app.php` 中的路由按控制器拆分为独立文件
- Index 控制器的路由保留在 `route/app.php`
- 其他每个控制器对应一个 `route/[控制器名小写].php` 路由文件
- 拆分后所有路由行为与拆分前完全一致（零功能变更）

## 涉及范围

| 范围 | 说明 |
|------|------|
| **新增文件** | `route/application.php`、`route/login.php`、`route/reset_password.php`、`route/signup.php`、`route/system_manage.php`、`route/user.php` |
| **修改文件** | `route/app.php`（仅保留 Index 相关路由） |
| **删除文件** | 无 |
| **代码变更** | 无业务代码变更，纯路由定义迁移 |

## 影响分析

- **业务逻辑**：无影响，仅路由定义位置变更
- **URL 路径**：无变化，对外暴露的端点保持一致
- **中间件/前置逻辑**：无变化
- **性能**：ThinkPHP 路由文件按需加载，无性能影响
