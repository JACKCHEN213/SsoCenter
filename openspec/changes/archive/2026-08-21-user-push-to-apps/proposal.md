# 提案：用户推送到第三方应用

## 变更 ID

`user-push-to-apps`

## 背景与动机

SSO Center 作为统一身份认证中心，管理着所有用户数据。当新用户注册或用户信息变更时，需要将用户信息同步推送到已注册的第三方应用系统中，实现用户数据的一致性和单点登录的完整性。

### 现状问题

1. **无推送配置**：应用注册时没有配置用户推送接口，系统不知道如何将用户推送到第三方系统
2. **无推送记录**：没有记录用户是否已推送到哪些应用，无法追踪推送状态
3. **无推送入口**：用户管理页面没有推送按钮，管理员无法手动触发推送
4. **无失败重试**：推送失败后没有重试机制

### 业务场景

- 管理员注册一个新的第三方应用，同时配置该应用提供的用户新增/修改/删除接口
- 管理员在用户管理页面点击"推送"按钮，查看该用户推送到各应用的状态
- 推送失败的应用支持重新推送
- 推送时系统向第三方接口发送用户信息，根据响应判断是否成功

## 变更目标

### 1. 应用推送接口配置

在应用添加/编辑表单中新增"推送接口配置"区域，管理员填写第三方系统提供的：
- 新增用户接口（URL + 请求头 + 请求体模板 + 成功判定规则）
- 修改用户接口（URL + 请求头 + 请求体模板 + 成功判定规则）
- 删除用户接口（URL + 请求头 + 请求体模板 + 成功判定规则）

### 2. 用户推送管理

在用户管理页面：
- 新增"推送"按钮
- 点击后弹窗显示推送状态面板：列出所有配置了推送接口的应用，展示推送状态（未推送/成功/失败/推送时间）
- 支持对单个应用重新推送
- 支持删除用户

### 3. 推送日志

记录每次推送的详细日志（请求/响应/状态），便于排查问题。

## 涉及范围

| 范围 | 说明 |
|------|------|
| **新增表** | `sc_site_push_api`（推送接口配置）、`sc_user_push_log`（推送日志） |
| **修改页面** | `index.html`（添加/编辑应用增加推送配置）、`user.html`（新增推送按钮和弹窗） |
| **新增服务** | `PushService.php`（推送执行引擎） |
| **新增控制器方法** | `Application` 保存推送配置、`User` 推送/重推/日志查询 |

## 影响分析

- **现有功能**：应用 CRUD、用户 CRUD 不受影响
- **数据库**：新增 2 张表，`sc_site` 不变更
- **安全**：推送请求的 Header 中可能包含第三方系统的认证 Token，需加密存储
